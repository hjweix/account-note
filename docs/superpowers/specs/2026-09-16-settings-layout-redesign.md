# 设置页布局重设计规范

日期：2026-09-16 · 状态：已实施 · 范围：`management.html` 设置 tab 的结构与样式（不涉及数据模型）

## 1. 问题（实测）

测量方法：真实 `dist/management.html` + `dist/management.js` + `dist/management.css`，桩注入 `chrome.storage`，数据量为「用了一阵子」的规模（22 个站点备注、12 个标签、8 个禁用站点、5 个站点共 10 条锚定），Playwright 量取 `getBoundingClientRect()`。脚本见 `/tmp/settings-measure.mjs`。

| 视口 | 设置页文档总高 | 折算屏数 | 横向利用率 |
|---|---|---|---|
| 1440×900 | 5622px | 6.2 屏 | 63% |
| 1728×1117 | 5622px | 5.0 屏 | 52% |
| 1920×1080 | 5622px | 5.2 屏 | **50%** |

卡片高度分解（纵向顺序）：

| # | 卡片 | 高度 | 列表项 |
|---|---|---|---|
| 1 | 外观设置 | 249px | — |
| 2 | 标签管理 | 969px | 12 条 |
| 3 | 已禁用网站 | 880px | 8 条 |
| 4 | 输入框锚定 | 1060px | 5 组 |
| 5 | 站点范围 | 1531px | 22 条 |
| 6 | 数据管理 | 277px | — |
| 7 | 关于 | 252px | — |

累计 5218px；页头 + tab 约 205px；其余为卡片间距与底部留白。

### 三个根因

1. **列表模块无高度约束** — `.tags-list` / `.disabled-sites-list` / `.field-anchors-list` / `.site-scope-list` 都是 `display: flex; flex-direction: column`，条目数增长直接转化为页面高度。四者合计 4440px，占设置页 **79%**。单条 `.disabled-site-item` / `.tag-item` 因 `padding: var(--space-4)` 约 52–60px 高。
2. **横向空间被写死** — `.settings-container { max-width: 900px }`，而 `.main-content { max-width: 1800px }`。屏幕越宽，右半侧空置越多，1920 下正好浪费一半。同时受害的是「列表行里放不下筛选框」——行宽只有 900px 减去内边距。
3. **三张站点级表各自为政** — 数据源不同、渲染函数不同、互不知晓：

   | 列表 | 数据源 | 渲染函数 |
   |---|---|---|
   | 站点范围 | 备注记录的 `domain`（`hostOf` 去重） | `loadSiteScopes()` |
   | 已禁用网站 | `disabledSites` 数组 | `loadDisabledSites()` |
   | 输入框锚定 | `fieldAnchors` 按 origin 分组 | `loadFieldAnchors()` |

   同一个站点最多在三处重复出现。用户想查「hwwt2.com 有什么设置」需在三张表里找三遍。且站点范围排在纵向第 5 位——最长的列表位于最深处。

## 2. 目标

- 设置页任意面板**单屏内可见**，页面级纵向滚动归零
- 横向利用率提升到 ≥60%，宽屏不空置
- 一个站点的全部站点级设置**在一处可见**
- 不改数据模型、不改存储键、不触发迁移

## 3. 布局骨架

设置 tab 内容区由「单列卡片堆叠」改为「左侧分区导航 + 右侧内容」。

```
┌──────────────────────────────────────────────────────────┐
│ 页头：账号备注管理                              [搜索]    │
├──────────────────────────────────────────────────────────┤
│ [备注] [设置]                                             │
├────────────┬─────────────────────────────────────────────┤
│ 分区导航    │  内容区（随导航切换，一次只显示一组）           │
│ 148px      │                                             │
│ sticky     │                                             │
└────────────┴─────────────────────────────────────────────┘
```

规律：

- **导航**：宽度 148px，`position: sticky; top: <页头高度>`，不随内容滚动。当前项用 `--primary-100` 底 + `--primary-600` 字。
- **内容区**：`grid-template-columns: 148px minmax(0, 1fr)`，内容列宽自适应，外层容器 `max-width: 1400px`（取代原 900px）。
- **面板切换**替代纵向滚动：同一时刻只渲染/显示一组卡片。
- **小于 1024px**：导航退化为顶部横向分段控件（`overflow-x: auto`），内容单列。

## 4. 分组

7 张卡片归入 4 组。分组依据是「配置对象」，不是「重要性」。

| 分区 | 内容 | 依据 |
|---|---|---|
| 外观 | 主题选择器 | 全局偏好，无列表 |
| **站点** | 站点范围 / 已禁用网站 / 输入框锚定 | 三者都是 host 级配置 |
| 标签 | 标签统计 | 备注内容的衍生统计 |
| 数据与关于 | 数据管理 + 关于 | 一次性操作与静态信息 |

## 5. 站点面板：三表合一

原三张表合成一张，一行一个站点。行结构：

```
[域名]  [备注 N] [已禁用] [锚定 M]        [范围 ▾]  [展开 ▾]
```

- **数据集**：三者 host 的**并集**（此前站点范围只列有备注的 host，会漏掉「只禁用无备注」和「只有锚定」的站点——这本身是个缺陷）。
- **徽章**：`备注 N`（有备注时）、`已禁用`（danger 配色）、`锚定 M`。无徽章的行只有域名与范围选择器。
- **展开**：行内展开该站详情——锚定记录列表（含单条移除）+ 备注弹窗启用/停用开关。取代原「已禁用网站」与「输入框锚定」两张表。
- **排序**：默认按域名升序；有徽章的排在无徽章之前？**否** —— 保持纯字典序，避免位置随编辑跳动。
- **筛选**：表头放筛选输入框（沿用备注列表的 `searchTerm` 过滤思路）+ 右侧「N 个站点」计数。筛选命中为空时显示空状态。
- **限高**：表体 `max-height: 520px; overflow-y: auto`，表头（筛选框 + 计数）固定不滚。
- **保留的手动添加入口**：原「已禁用网站」可手动输入任意域名（不限于有备注的站点）。改为表头右侧「添加站点」动作，弹出的输入框允许填任意域名，提交后该域名作为一行「无备注」的禁用站点出现。

## 6. 其他两个面板

### 标签面板

标签从「列表行」改为「chip 云」——标签本身是短词，一行一个浪费 52px 才换来一次点击。

- 布局：`display: flex; flex-wrap: wrap; gap: 8px`，胶囊为 `标签名 + 计数`。
- **重命名与删除保留**（实施时核对代码发现：标签列表并非只读，`enterTagEditMode` / `renameTag` / `deleteTag` 三个写路径必须留住）。动作随胶囊走：
  - 点胶囊主体 → 原地变输入框（`settled` 标志保证「回车提交 + 随后 blur」只生效一次），回车保存 / Esc 取消
  - 胶囊右侧 `✕` → 走既有的 `showConfirmDialog` danger 对话框 → `deleteTag`
- 预计高度：969px → 实测 182px（含标题与说明；12 个标签）。
- 空态沿用现有 `noTags` 文案。
- 注意：胶囊是 flex item，`inline-flex` 会被浏览器**块化为 `flex`**（CSS 规范行为），断言要按计算结果写。

### 外观 / 数据与关于面板

内容量小，保持卡片形态，仅两处调整：

- 外观面板：主题选择器三选项横排（现状已如此），卡片宽度自适应内容区，不再受 900px 限制。
- 数据面板：`导出 / 导入` 与 `清除所有数据` 分成两张卡（危险操作独立成卡），关于信息第三张卡。

## 7. 收益（实施后实测）

测量方法同 §1：真实 `dist` + 同一份大数据量（22 个站点备注、12 个标签、8 个禁用站点、10 条锚定），1440×900 与 1920×1080 两种视口。

| 指标 | 实施前 | 实施后 |
|---|---|---|
| 设置页文档总高（1440×900） | 5622px（**6.2 屏**） | 900px（**1.0 屏，零页面滚动**） |
| 设置页文档总高（1920×1080） | 5622px（5.2 屏） | 1080px（**1.0 屏**） |
| 横向利用率（1440） | 63%（容器 900px） | **93%**（容器 1344px） |
| 横向利用率（1920） | 50%（容器 900px） | **78%**（容器 1400px） |
| 站点信息分布 | 3 张表，同一站点最多出现 3 处 | **1 张表，1 行 1 站** |
| 标签面板 | 969px | 182px |
| 站点面板 | 3471px（三张表合计） | 639px（22 个站点内滚） |

面板高度（1440×900）：外观 249 / 站点 639 / 标签 182 / 数据与关于 553。

表体高度不用固定值，取 `clamp(180px, calc(100vh - 632px), 560px)`——632px 为实测的「页头 + tabs + 面板固定部分 + 间距」之和。矮屏自动收，高屏给足行数。

## 8. 实施要点

**只改展示层，数据模型零改动。**

- `management.html`：设置 tab 内容区重写为「导航 + 面板」结构。7 张卡的 DOM 保留在对应面板中，避免 JS 侧查找失败。
- `src/management.js`：
  - 新增 `setupSettingsNav()`——绑定面板切换，记录当前分区（`sessionStorage` 记忆，关闭页面即失效，不落 `chrome.storage`）。
  - 新增 `loadSitesPanel()`——合并三源构建 host 集合，渲染单表。原 `loadSiteScopes()` / `loadDisabledSites()` / `loadFieldAnchors()` 改造为其内部的数据准备与详情渲染，**写入路径（`chrome.storage.local.set` 的目标键）一律不变**。
  - 行展开状态保存在内存对象中，重渲染时按 host 恢复。
- `src/management.css`：新增导航、站点表、chip 云样式；`.settings-container` 的 `max-width` 由 900px 改为 1400px。删除三张旧表的列表样式。
- **i18n**：新增 key 需同步补 `zh_CN` 与 `en`（沿用既有规则：`getMessage()` 未收录会返回 key 本身，`|| 兜底` 永不生效）。新增预计 8–10 条：`settingsNavAppearance` / `settingsNavSites` / `settingsNavTags` / `settingsNavData` / `siteFilterPlaceholder` / `siteCount` / `anchorSummary` / `noteCountShort` / `popupEnabled` / `addSiteAction`。
- **门禁**：`npm run build` + `check:css` + `check:i18n` 必须全绿。chip 云不再使用 `.tag-item` 系列类名，`check:css` 的作用域检查需一并确认无裸标签选择器。

### 验证（已执行）

新增 `settings-layout-verify.mjs`（44 断言），断言：导航四项与文案、默认分区、面板唯一可见、点击切换、`sessionStorage` 记忆、**三源 host 并集去重**、三源重叠站点只出现一行、锚定/禁用独有站点入表、站点计数、表体限高自适应、三类徽章各自只在应当出现时出现、筛选收敛与「命中/总数」计数、筛选无命中空态、行展开、详情列出跨 origin 的锚定、多 origin 时标注来源、锚定移除写入正确且不影响其他站点、重渲染保持展开态、徽章随数据更新、启用弹窗摘除同 host 全部 origin、停用写回、范围选择写入与切回删键、胶囊云布局与数量、旧列表行消失、点胶囊原地编辑、重命名写入备注 tags、设置页零页面滚动、最高面板单屏可见、两栏网格、容器宽度上限。

既有回归中 `netscope-mgmt-verify` 有 3 条断言绑定旧结构（`#siteScopeList` / `.site-scope-host` / 卡片标题「站点范围」），已随实现更新。其余六套无需改动。

**合计 232 断言全绿**：settings-layout 44 + m1 30 + tag-inline 7 + m2 16 + m3 16 + uxfix-content 22 + uxfix-mgmt 22 + netscope-unit 41 + netscope-integration 25 + netscope-mgmt 9。

测试环境注意：本套脚本改用**本地 http 服务**而非 `page.setContent`——opaque origin 下 `sessionStorage` 读取会抛 `SecurityError`，分区记忆这类断言无从验证。

### 未按原计划实施的部分

- 原计划「渲染/显示一组卡片」按需切换，实际实现为**四组面板都在 DOM 中、用 `hidden` 切换**。原因：`initI18nTexts()` 与 `setupSettingsSidebar()` 在初始化时即按 id 取节点，若按需创建需重排初始化时序，收益不足。


## 9. 未纳入

- **「并入指定域」档位**（让两个平级子域互通）：与本次布局无关，仍留待实际诉求
- **设置项搜索**：跨面板全局搜索配置项。面板数只有 4 个，收益不足
- **列表虚拟滚动**：站点数达到数百时才有必要，当前 `max-height` + 原生滚动足够
