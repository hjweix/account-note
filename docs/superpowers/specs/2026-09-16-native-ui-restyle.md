# Account Note 原生化 UI 重设计（Native Restyle）

**设计日期**: 2026-09-16
**涉及版本**: 1.1.0 → 1.2.0（建议）
**设计基准**: Chrome 内建密码管理器气泡（Material Design for Chrome / CrOS 2020 规格）

## 1. 问题诊断

当前三端 UI 是"玻璃拟态"（glassmorphism）风格，与宿主站点差异过大：

| 问题 | 现状 | 为什么是问题 |
|------|------|-------------|
| 半透明 + 背景模糊 | `backdrop-filter: blur(24px)`、`rgba(255,255,255,0.85)` | 弹窗内容透出宿主页面，任何花哨站点都会把弹窗搅脏 |
| 多层叠加阴影 | `0 8px 32px` + 双 ring + inset 高光 | 视觉重量大，像浮在页面上的独立 app，不像浏览器的一部分 |
| 品牌色过重 | indigo 紫色系（#6366f1）渐变 + 彩色标签 | 与任何站点配色都会冲突；Chrome 原生 UI 用中性灰 + 单一蓝色点缀 |
| 弹性动画 | `--ease-bounce` 0.25-0.4s | 原生 UI 是 150ms 快速淡入，无弹跳 |
| 弹窗定位在输入框右侧 | 硬编码 260/270 估算宽度翻转 | 密码管理器下拉固定出现在字段正下方；且魔数已记待办 |

## 2. 设计基准：Chrome 密码气泡的解剖

Chrome「保存密码？」气泡的可复用特征：

1. **不透明实心表面**——浅色 `#FFFFFF`，深色 `#292A2D`，零透明度、零模糊
2. **8px 圆角**，单层柔和阴影 `0 1px 3px rgba(0,0,0,0.3)` + 1px 分隔边
3. **系统字体栈**（`system-ui`），正文 13px，标题 14px/500
4. **中性色主体 + 单一强调色**：正文 `#202124`、次级 `#5F6368`、强调 `#1A73E8`（暗色对应 `#E8EAED` / `#9AA0A6` / `#8AB4F8`）
5. **行式布局**：hover 行变 `#F1F3F4`（暗色 `#3C4043`），无卡片嵌套感
6. **文字按钮**：操作用无背景蓝字按钮，不用彩色实心按钮
7. **锚定字段下方**出现，150ms 淡入 + 轻微 scale(0.98→1)

## 3. 统一 Design Token（三端共用）

```css
/* 亮色（默认） */
--surface: #ffffff;            /* 弹层实心表面 */
--surface-hover: #f1f3f4;      /* 行 hover */
--border: rgba(0,0,0,0.10);    /* 1px 分隔 */
--text-primary: #202124;
--text-secondary: #5f6368;
--accent: #1a73e8;             /* 唯一强调色，替换 indigo */
--star: #f9ab00;               /* 收藏星标，保留品牌记忆点 */

/* 暗色 */
--surface: #292a2d;
--surface-hover: #3c4043;
--border: rgba(255,255,255,0.10);
--text-primary: #e8eaed;
--text-secondary: #9aa0a6;
--accent: #8ab4f8;
--star: #fdd663;

/* 形状与动效 */
--radius: 8px;                 /* 弹层容器；内部小控件 4-6px */
--shadow: 0 1px 3px rgba(0,0,0,0.3), 0 4px 12px rgba(0,0,0,0.15);
--motion: opacity 0.15s ease, transform 0.15s ease;  /* 入场 scale(0.98)→1 */
--font: system-ui, -apple-system, 'Segoe UI', Roboto, sans-serif;
```

**规则**：删除 `backdrop-filter` 全部使用；删除所有渐变背景；三端 CSS 的色彩变量统一收敛到上面这组（popup.css / management.css 现各自有一套 `:where()` 变量块，合并语义、保留各自前缀命名以过 `check:css` 门禁）。

## 4. 弹窗（overlay）重设计——核心

### 4.1 结构重排

现结构（textarea + 标签 + footer 按钮排）→ 新结构（行式）：

```
┌──────────────────────────────────┐
│ ● github.com            ★    ✕  │  ← 头部行：站点域名 + 收藏 + 关闭
├──────────────────────────────────┤
│ 备注正文（13px，阅读态限 3 行，   │  ← 正文行：纯文本，点击原地进入编辑态
│    点击进入编辑，全文可见）       │
├──────────────────────────────────┤
│ [工作] [常用]            ＋标签  │  ← 标签行：中性 chip，右侧文字按钮
└──────────────────────────────────┘
```

- 头部行提供"这是谁的弹窗"上下文，替代现在的无标题裸面板
- 备注正文去 textarea 边框盒：**阅读态是纯文本**，点击即原地进入编辑态（临时变为无边框 textarea，全文可见），Esc 取消编辑、失焦保存
- **没有独立的「编辑」「收起」「展开」按钮**——点击正文是唯一入口，退出编辑即回到 clamp 3 行的阅读态，展开/收起随编辑态自然发生
- 标签 chip 中性化：`surface-hover` 背景 + `text-secondary` 前景，hover 才显 ×
- 「＋标签」在标签行右端；底部无按钮行
- 空备注（新增场景）：正文行显示 placeholder，点击即编辑，行为同上

### 4.2 定位修正（维持右侧，实测替代魔数）

**定位原则**：弹窗是辅助角色，必须避让浏览器原生 UI——字段正下方是密码管理器的地盘（它记密码，我们区分账号，语义互补、位置错开）。

- 默认出现在**字段右侧**，垂直方向与字段顶部对齐（现行为保留）
- 右侧放不下 → 翻转到字段**左侧**；翻转判定用**实测弹窗宽度**（创建后读取 `offsetWidth`），替代硬编码 260/270 魔数
- 左右都放不下 → 夹紧在视口内（左缘最小 8px）
- 垂直方向：底部越界时上移夹紧，实测弹窗高度后计算
- 弹窗宽度自适应内容：`min(360px, max(280px, 内容所需宽))`，不与字段宽绑定
- `popupPositionCache` 缓存机制保留，窗口 resize 时重算
- `getOverlayRoot()` 挂 `documentElement` 的现有机制不变

### 4.3 主题策略

维持现状口径：跟随系统 `prefers-color-scheme`（与 Chrome 原生 UI 一致——它也不探测站点配色）。站点是深色而系统是浅色时，白底弹窗依然成立（Chrome 自己就是这样）。

## 5. Popup（工具栏弹窗）

- 头部：扩展名 + 图标，去掉渐变横幅
- 备注列表改为行式：左侧头像/域名，右侧收藏星标；hover 行 `surface-hover`
- 主按钮「手动指定输入框」改为蓝色文字按钮置底；提示条（pickerHint）配色同步 token
- 弹窗宽度维持当前（Chrome 扩展 popup 默认 360px 上限内），无需改动布局骨架，只换皮

## 6. 管理页（management）

- 去玻璃拟态：卡片改白底实心 + 1px 边 + 8px 圆角；删除 `backdrop-filter` 与渐变 hero
- 网格保持 `minmax(320px, 1fr)`（沿用 2026-04-22 紧凑卡片规格的骨架），视觉规格替换为第 3 节 token
- 收藏卡片顶部 2px 琥珀条保留（唯一保留的装饰，识别成本低）
- 头像渐变改为中性底 `surface-hover` + 首字母 `text-secondary`；收藏色 / 删除红色语义不变

## 8. Trade-off 与风险

| 决策 | 得 | 失 / 风险 | 缓解 |
|------|----|-----------|------|
| 放弃玻璃拟态改实心 | 与宿主站点零干扰，原生感 | 视觉"个性"下降 | 用收藏星标琥珀色 + 头部行保留品牌记忆点 |
| 正文点击即编辑，无「编辑/收起/展开」按钮 | 弹窗少一行、最接近原生 | 可发现性下降（长文本"看全文"要靠点正文） | 接受：点正文即编辑是通用交互习惯；Esc 取消无风险 |
| 定位维持字段右侧（实测宽度替代魔数） | 不遮挡浏览器密码管理器，两工具互补 | 占用横向空间；极窄视口下弹窗显大 | 左右翻转 + 视口夹紧兜底 |
| 跟系统而非跟站点配色 | 实现简单、与 Chrome 行为一致 | 深色站点 + 浅色系统时弹窗偏亮 | 接受（Chrome 同款行为） |
| 三端统一 token | 维护成本低、观感一致 | 一次性改动面大 | 分三批交付，批内回归 |

## 9. 验收标准

1. 在 GitHub（浅/深）、任意强配色站点上截图：弹窗表面完全实心、无透色
2. 弹窗出现于字段正下方，视口边缘不溢出，无需刷新即可重定位
3. 明暗系统主题切换弹窗即时跟随
4. `check:css`（无裸选择器、无重复规则）、`check:i18n` 通过
5. 既有 84 + 19 + 21 断言回归全绿
