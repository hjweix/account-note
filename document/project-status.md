## 本次会议完成内容
1. 修复「部分站点不弹出备注框」（核心 Bug）
   - 根因定位：content script 以 `document_idle` 注入，首屏扫描入口挂在 `DOMContentLoaded` 上永不触发；唯一的实际入口 MutationObserver 在「渲染完就静止」的 SPA 页面上也不会触发

## 技术难点解决
1. 定位「时好时坏」的隐性 Bug：SPA 页面 DOM 静止后 MutationObserver 不触发，字段从未被绑定，表现随页面是否继续变动而随机
2. 用事件委托替代节点级绑定，从根本上消除 SPA 场景下的失效，节点被重建也仍然生效
3. 建立可复现的实测手段：在真实站点注入构建产物 + 页面侧探针，同时验证「功能生效」与「对页面无副作用」
4. CSS 隔离不靠 Shadow DOM 重构，改用「容器限定 + 变量收窄 + 动画名加前缀」，并用「裸类名探针 + 阳性对照」量化验证零泄漏
5. **识别判据的单信号失效问题**：实测证明任何单一信号都不够——dcps 上「取密码框前最近的文本框」会选中前端框架的反 autofill 蜜罐框（无 id/name + `tabindex="-1"`），GitHub 上则靠 `autocomplete="username"` 单独就能命中。最终采用加权评分，把矛盾信号放在同一把尺子上比较
6. **真实站点验证通道**：Playwright 启动的 Chromium 不继承 shell 代理导致真实站点不可达；改用 ego-browser 把评分核心代码注入扩展隔离世界，对真实 DOM 逐个 input 打分（纯计算，不挂监听、不弹窗、不污染页面），拿到了 GitHub / dcps 的真实得分明细

## 数据兼容性实测结论（手动锚定记忆的升级安全评估）

**评估问题**：二期「手动锚定记忆」需新增 storage key（如 `fieldAnchors`），是否会导致既有用户数据受影响、无法平滑升级或丢失？

**结论：不会。升级是安全的，且已被两条证据链证实。**

### 证据一 · 静态审计（全量 storage 读取路径）

`chrome.storage.local.get(null)` 全表读取共 11 处，逐处核验过滤口径：

| 位置 | 用途 | 过滤口径 | 新 key 是否会被误处理 |
|---|---|---|---|
| management.js:86 | 批量迁移 | `note && note.domain && note.note && note.username` | 否 |
| management.js:249 | 备注列表加载 | 同上 | 否 |
| management.js:444 | 搜索 | 无本地过滤，**下游 `displayNotes()` 再过滤**（:285） | 否 |
| management.js:897 | 调试日志 | 只打印 key 名 | 否 |
| management.js:1110 / 1219 / 1714 / 1761 / 1801 | 取标签 / 导出 / 重命名标签 / 删除标签 / 标签统计 | 同一谓词 | 否 |
| management.js:1284 | 导入前查冲突 | 只按 `note.key` 索引 | 否 |
| popup.js:50 | 弹窗按站点过滤 | `note.domain === domain && …` | 否 |

其他保障：
- **无 `chrome.storage.onChanged` 监听**（全仓仅一处 `chrome.runtime.onMessage`），不存在「任意变更被当备注变更」的通路；
- **无整表回写**：所有 `set()` 要么是定点 `{key: val}`，要么是由备注集合构建的 `updates` 映射，不存在 `set(整个get结果)` 的写法；
- **既有先例**：`theme` / `disabledGlobal` / `disabledSites` 三个非备注 key 已与备注共存于同一 storage 并行工作至今，新增第 4 个遵循同一已证模式；
- 唯一的全量删除是用户手动触发的「清除所有数据」按钮（`storage.local.clear()`），该行为与本次改动无关。

### 证据二 · 真机实测（真实扩展 + 真实 chrome.storage，14 个断言全过）

构造一位老用户的混合 storage（老格式备注无 `tags`/`isFavorite`、更老格式缺 `key`/`createTime`、已合规新格式备注、既有非备注 key、新增 `fieldAnchors`、未知未来 key，共 8 个 key），加载 `dist/` 后打开管理页触发真实迁移与渲染：

| 更老格式备注补上 `key` 与 `createTime`，备注文本保真 | ✅ |
| 已合规备注逐字段零改写（键序无关深比较） | ✅ |
